# 01 · 聚类簇命名

## 用途

`cluster.py` 跑出来的簇只有关键词和代表消息，没有名字。命名和"哪个簇该扔掉"必须靠读，
靠关键词硬拼出来的名字（"孩子儿子家长家里女儿"）等于没有。

## 输入

```bash
python -m wxchat_analysis cluster --input 群.jsonl --k 12 > clusters.txt
```

把每个簇的关键词、代表消息贴进模板。代表消息至少给 8 条，跨度要大（不同月份、
不同发言人），只给 3 条会让模型按关键词编。

## 提示词正文

```text
下面是一份群聊语料跑出来的 {{K}} 个消息簇。每个簇有：高频词（按簇心权重排序）、
按时间分布的峰值月份、以及按置信度排的 10 条代表消息。

请对每个簇做两件事：判断它是不是一个真实话题，如果是，给它起名。

输入：
{{clusters.txt 的内容，每个簇单独一段}}

规则：

1. 名字是名词短语，4~8 个汉字，能直接放进折线图的图例。不要"日常交流""杂项"
   "其他讨论"这类空名。
2. 判断"垃圾桶簇"的判据，满足任意两条就标 discard：
   - 代表消息之间互相没有关系，一个人说吃的一人接梗
   - 高频词是 hhh、几点、名字、表情这类填充语
   - 峰值月份分布在整个时间轴上（说明是背景噪声，不是事件）
   - 除了关键词，讲不出这个簇在聊什么
3. 两个簇如果讲的是同一件事，只保留覆盖消息多的那个，另一个标 merge 并写明合并到谁。
4. 每个保留的簇必须给不少于 3 条证据索引，索引是代表消息行首的数字。
5. 不要根据关键词反推情绪或动机，你只看到了 10 条消息，不足以判断。

输出格式，严格 JSON，不要代码块以外的任何文字：

{
  "clusters": [
    {
      "id": 0,
      "keep": true,
      "name": "育儿与带娃",
      "why": "代表消息集中在接送、作业、家长群三类，跨 4 个月稳定出现",
      "evidence": [12345, 23110, 30288],
      "merge_into": null
    },
    {
      "id": 5,
      "keep": false,
      "name": null,
      "why": "高频词是 hhh 和朋友，代表消息互不相关，峰值散布全年",
      "evidence": [],
      "merge_into": null
    }
  ],
  "notes": "如果有哪些话题是词典法主题覆盖不到的，在这里列一句，用 cluster id 指代"
}
```

## 验收

- 名字能直接当图例用，不用再改；
- 被 discard 的簇加起来不超过总数的三分之一（超过说明 k 取大了，回去调 `--k`）；
- `notes` 里提到的"词典漏掉的话题"要去 `topic_lexicon.json` 里补词，下一轮不再靠聚类发现。

## 已知失败

- **给每个簇都起名**。模型倾向于说"这个簇也有点意思"，结果垃圾桶簇也进了报告，
  图例里出现"日常闲聊"。要在提示里明确 discard 是正常操作。
- **名字太长**。"关于孩子教育和家庭作业的讨论"进不了图例。
- **只读关键词就下结论**。代表消息是给交叉验证用的，提示里已经要求给索引，
  没给索引的条目要求在 `04` 里删掉。

## 下一步

保留的簇名直接替换 `report_data.json` 里 `topic_share` 之外的补充维度；
如果某个簇对应的议题在词典里没有，优先补词典，比每次跑聚类便宜。
