# 03 · 关系深挖（单人 / 双人 / 事件）

## 用途

从几十万条里挑出十几段，还原一条关系或一件事的来龙去脉。这是全套流程里最容易写坏的
一环，因为模型会自动补动机、补因果、补结局，写成小说。

## 输入

```bash
# 1. 先定位：按词找人找事
python -m wxchat_analysis ctx --input 群.jsonl --search "分手|异地|他|对象" --pad 15 --limit 40

# 2. 按人取全部发言（只取有实质内容的，pad 0）
python -m wxchat_analysis ctx --input 群.jsonl --who 某人 --pad 0 -o 某人_all.txt

# 3. 挑出关键时段，逐段取窗口
python -m wxchat_analysis ctx --input 群.jsonl --range 12340 12420
```

第一轮不要急着写。先把窗口读一遍，列出 8~15 个"信息量高的时段"（有前因后果、有转折、
有多人参与），第二轮再喂给模型。一次给 40 个窗口会让它开始平均化处理，写出来全是套话。

## 提示词正文

```text
下面是一个群聊里与「{{对象}}」相关的 {{N}} 段对话，按时间排序，已带消息索引。
我要的不是故事，是可核对的事实和结构。

第一步，只做事实提取，不下判断：

按时间列出发生了什么。每条格式：
yyyy-mm-dd | 一句话说清这件事 | [索引][索引]

要求：
- 一件事一条，不要把几件事并成一条；
- 拿不准的写"（不确定）"；
- 同一天的多条最多合并成一条；
- 只在对方有直接发言时才算"发生了"，别人转述的单独标注"转述"；
- 没有日期的推测不要写进来。

第二步，结构判断。3~5 条，每条两到三句：
- 判断本身一句话；
- 支撑证据指到具体索引；
- 如果这条判断基于一方的自述，必须写明"按她的说法"，不要写成客观事实。

第三步，写出数据看不到的部分。3 条以内，每条一句话：
- 哪些关键节点只有一方叙述；
- 哪些时段没有记录（不是没发生，是导出里没有）；
- 哪些结论需要当事人确认才能成立。

输入：
{{ctx 输出的窗口，每段带 --- [start..end] label --- 头}}

纪律：

- 只写记录里有的。她没说他为什么沉默，就不要写"他在逃避"。
- 区分"她说他如何"和"他如何"。前者是她的叙述，后者需要他自己的发言。
- 不写结局。记录断在哪儿就写到哪儿。"静默断联"不等于"分手"，除非有人明确说了。
- 不煽情。不写"深夜的对话框里"、"两个人都很孤独"这类句子。
- 不用破折号、中文冒号、翻案句。
- 引用原话用「」，一字不改。

输出三段，用【时间线】【结构】【未解决】开头，不要其他任何说明文字。
总长控制在 1200 字以内。
```

## 验收

- 时间线每条都有索引，且索引能在输入里找到；
- 结构判断里至少一半写明"按某人的说法"；
- 未解决部分不为空。空的一定是在编，因为群聊记录永远缺东西；
- 全文没有心理诊断词（依恋类型、原生家庭、投射……），除非是当事人自己说的原话。

## 已知失败

- **写成小说**。"她想要的其实很简单"这类句子是模型在替人物抒情，一律删。
- **闭环强迫症**。模型喜欢给关系一个结局或一个教训。提示里明确要求"不写结局"。
- **单方叙述升格为事实**。只有她的发言时，她对他的描述是她的解读，不是事实。
  这一条要在提示里重复，因为模型很容易忘。
- **时间线塞满细枝末节**。10 条以上的时间线读者就不看了，压到 6~8 条。
- **把群里其他人的玩笑当评价**。群友的调侃是现场气氛，不是判断依据，最多写成
  "当时群里的反应是……"。
