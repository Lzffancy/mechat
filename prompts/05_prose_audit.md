# 05 · 文案返修

## 用途

正文写完后，用脚本抓"形状问题"（冒号、破折号、翻案句、黑话），再让模型逐条改写。
脚本负责找，模型负责改，两边缺一不可——脚本改出来的句子是病句，模型自查会漏掉一半。

## 输入

```bash
python -m wxchat_analysis prose --html 报告.html
```

输出类似：

```
汉字数 5093  问题 97 条 / 待判断 4 条
  ✗  40  中文冒号: ……的关系：两个人都在回避……
  ✗  57  破折号: ……他不接暗示，她又只会暗示——于是……
  ✗   6  翻案句: 不是…而是 ← 不是不爱，而是不敢说
  ?   1  用词: 方法论
```

## 提示词正文

```text
下面是一份中文长报告的体检结果和原文。请逐条给出改写。

体检结果（脚本抓的，只有位置和类型，没有语义）：
{{prose 输出}}

原文（只贴被标记的段落，不要贴全文）：
{{段落}}

改写规则：

1. 中文冒号改成句号，把后半句拆成独立句子。不要改逗号，那是换汤不换药。
2. 破折号拆成两句。不要机械换成逗号，会造出超长句。
   「他不接暗示，她又只会暗示——于是问题永远解不开」
   → 「他不接暗示，她又只会暗示。问题就一直卡在这里。」
3. 翻案句拆成两句陈述。
   「问题不在爱不爱，而在于两个人都不会说」
   → 「问题出在两个人都不会说。爱不爱是另一件事。」
4. 黑话换成具体动作。
   「把关系沉淀下来」→「把关系维持在一个稳定的状态」
   「赋能对方」→ 说清楚具体做了什么
5. 借喻动词换成平实说法。
   「先把事实钉住」→「先说已经确定的事实」
   「打通这个环节」→「让这两步接上」
6. 只改形式，不改意思。原意是"可能"，改写后不能变成"一定"。
7. 引用的原话（在「」里）一个字都不许动，包括标点。

输出严格按这个格式，每条一行，用 JSON 数组：

[
  {"old": "原文片段（够定位，20~40 字）", "new": "改写后", "why": "冒号拆分"},
  {"old": "...", "new": "...", "why": "破折号拆句"}
]

注意：
- old 必须是原文里连续出现、且只出现一次的片段，否则替换会失败；
- 不要动 HTML 标签和属性，old/new 里不要包含标签；
- 警告项（用词、长句）先判断是不是本义，"方法论"讲方法论本身就不用改，
  你可以给 {"old": ..., "new": ..., "why": "warn-保留"} 表示看过但保留。
```

## 落地

把模型给的数组直接写成替换脚本，**必须带唯一性断言**：

```python
R = [...]  # 模型输出的 (old, new)
miss = []
for old, new in R:
    n = s.count(old)
    if n != 1:
        miss.append((n, old[:60]))
        continue
    s = s.replace(old, new)
print("applied", len(R) - len(miss), "/", len(R))
for n, t in miss:
    print(f"  MISS({n}): {t}")
```

`MISS` 通常有两种原因：原文里有 `<b>` / `<span>` 把句子打断，或者片段不够唯一。
补几条手工替换就行，不要为了让它自动匹配去放宽断言。

## 验收

- 再跑一次 `prose --html`，硬禁令清零；
- 总字数变化在 ±5% 以内（缩水太多说明改写在删信息）；
- 抽三条对照原文，确认语义没变。

## 已知失败

- **机械替换造病句**。破折号统一换逗号是最常见的偷懒，"关系很浅——她一直在试探"
  换成"关系很浅，她一直在试探"读起来还行，但五处连在一起就散了。要求逐句判断。
- **改写时偷偷加强语气**。"她可能在意"改成"她在意"就是把推断升成事实。
- **顺手删掉数字**。"81.8%"改成"绝大多数"看起来更顺，信息量直接没了。
- **动了引用的原话**。这是最严重的一类，必须回到原文核对。
