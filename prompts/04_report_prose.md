# 04 · 报告正文

## 用途

把 `report_data.json` 里的数、前几步的事实卡，写成一份能读的正文。这一步只做取舍和行文，
**不引入新事实**。

## 输入

```bash
python -m wxchat_analysis report --input 群.jsonl --members 群_members.csv -o out/
# out/report_data.json 就是输入；不要整份贴，按下面的清单摘
```

摘取清单（贴进模板的 `{{data}}`）：

- `meta` 全给；
- `monthly` 全给；
- `topic_share` 前 8 条 + `meta.topic_coverage`；
- `nodes` 前 15（含 `pagerank` / `between` / `q_in` / `kcore` / `community`）；
- `communities` 全给（人多时只给前 3 个社群的前 10 人）；
- `lift` 前 10、`strong_pairs` 前 10；
- `rhythm.monthly` / `rhythm.latency` 前 8 / `rhythm.bursts` 前 5；
- 词频前 60。

## 提示词正文

```text
下面是一个微信群的分析数据，以及前面步骤得出的结论。请写出报告正文。

数据：
{{report_data.json 摘取部分}}

事实卡（带索引，来自原文）：
{{01/02/03 的输出}}

结构，五节：

1. 开头，三到四句。用一个确切的事实开场（时间、条数、人数），不要悬念，不要提问，
   不要"在这个信息爆炸的时代"。这一段要让读者知道这份报告在说什么。
2. 基本盘，两段。量、跨度、活跃度、集中度。每个数后面跟半句解释它意味着什么，
   不要只报数。
3. 在聊什么，两到三段。先用主标签口径给结构，再挑两三个话题说明它们集中在什么人身上。
   口径必须写清楚，提及量和互斥主标签不能混着用。
4. 谁和谁，两到三段。结构是什么样（社群、枢纽、边缘），然后给两三个具体的人或对。
   引数据时给具体数字，不要"非常高"。
5. 结论，三到五句。只写数据支撑的判断。不确定的写不确定。

硬性要求：

- 中文冒号（：）一个都不要用，改成句号或逗号。
- 破折号（——）、单破折号（—）一个都不要用。
- 不用翻案句：不是……而是 / 并非……而是 / 不在于……而在于 / 与其说……不如说 / 看似……实则。
- 不用这些词：赋能、抓手、闭环、沉淀、打通、锚定、钉住、解剖、底层逻辑、全链路、
  组合拳、认知、维度、矩阵、生态、增长飞轮。
- 不用路标句：值得注意的是、更微妙的是、还有一层、换句话说、从某种意义上说。
- 每个数字必须来自上面的数据，不许自己算，不许"大约"。
- 标题短，一行放得下，不超过 12 个汉字。
- 段落不超过 4 句，句子不超过 40 字。

**不要输出 HTML，不要写 CSS。** 排版由 `python -m wxchat_analysis html` 负责，
模板是纸媒杂志风（宋体正文、单色强调、620px 单栏、手机优先）。你只交 Markdown：

- 分节标题 `## 00`（封面导语）、`## 01` 到 `## 06`，对应报告的六个章节
- 段落直接写，空行分段
- `>` 开头是引语块，`::` 后面接来源（可省）
- `- ` 开头是列表
- `**文字**` 是加粗
- 数字、图表、排行榜都不用你写，它们由代码从 report_data.json 现算

输出只有这些文字块。不要在开头写"以下是我为你撰写的报告"。
```

## 为什么不让模型碰排版

模型写出来的 HTML 有两个固定问题：一是每次生成的 CSS 不一样，两版报告的同一段文字
长得不同，读者以为换了口径；二是它会自己加 `<style>` 覆盖模板，把字体分工和单色强调
这两条最关键的规则破坏掉。模板里已经有的东西，模型不重复造。

## 验收

```bash
# 生成：$ 是命令，不是模型输出
python -m wxchat_analysis html --data out/report_data.json --prose 正文.md -o 报告.html

# 体检：正文和成稿各跑一遍
python -m wxchat_analysis prose --text 正文.md
python skills/human-writing/scripts/check_prose.py 正文.md
```

要求：中文冒号 0、破折号 0、翻案句 0、黑话 0。警告项（用词、长句）人工看。
完整规则在 `skills/human-writing/`，写作纪律的源头在那里。

再手工核对三件事：

1. 正文里每个数都能在 `report_data.json` 找到，抽样核对 5 个；
2. 事实卡里的结论没有被写成更强的版本（"她可能在意" → "她很在意"就是升级，不许）；
3. 主题占比的口径前后一致。

## 已知失败

- **报数不解释**。通篇"发帖 48,400 条，成员 41 人，活跃日 224 天"，读者看完不知道要说什么。
  每个数后面跟半句判断。
- **开头卖关子**。"这个群有一个秘密"这种写法在数据分析报告里是硬伤。
- **结论超出数据**。基尼 0.713 只能说明发言集中，不能说明"少数人控制话语权"。
- **一篇文章里两套口径**。提及量 15.8% 和主标签 16.8% 混着写，读者会以为数字自相矛盾。
- **删掉数字保文采**。宁可句子难看，也不要"几乎每个人"这种模糊表述，直接给 81.8%。
