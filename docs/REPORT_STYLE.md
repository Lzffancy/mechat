# 报告版式：纸媒杂志风

排版规则固化在 `wxchat_analysis/templates/magazine.css`，渲染逻辑在 `htmlreport.py`。
改样式前先读这份文档，否则很容易把"杂志感"做成"配色看起来旧一点"。

## 六条核心规则

1. **字体分工** —— 正文宋体（`Songti SC / Noto Serif SC / SimSun`），
   标签、日期、数字、注释一律无衬线。**这一条比配色重要得多**，是杂志感的主要来源。
2. **单色强调** —— 全篇一个强调色 `#a63a28`（编辑部红）。强调色覆盖超过 30% 面积，
   层次反而消失，只剩花。
3. **纸感** —— `--paper:#faf8f3` + 横向纸纹（`repeating-linear-gradient` 1px/4px，
   透明度 .015）。再明显一点就像扫描件。页面外 `--bg:#e9e4d9` 暖灰，让纸浮起来。
4. **线条体例** —— 章节头 1.5px 粗线起头 + 红色编号 + 衬线大标题；结论框 2.5px/1px 双线；
   引语用上下细线（pull quote），不用左侧色块。
5. **首字下沉** —— 首节首段 `::first-letter` 54px 红色宋体，float 占两行。
6. **栏目标签** —— `.sub` 是短红线 + 小字字距 .18em，不用彩色圆角块。

## 布局

- 单栏 `.page{max-width:620px;margin:0 auto}`，**不是响应式兼容，是默认就按手机尺寸设计**；
- 手机（≤480px）padding 20px、h1 24px；桌面（≥700px）`.page` 加 `margin:34px auto`、
  h1 38px，卡片区在桌面才分两栏；
- 正文 17px / 行高 1.88（手机上 16px / 1.85）。宋体行高低于 1.8 会显挤，高于 1.95 会散。

## 图表

**柱状图和横条图用 HTML + CSS，不用 SVG。** 这是实测结论：SVG viewBox 宽度 560，
在 393px 的手机上被缩到 0.64 倍，9px 的轴标签实际只剩 6px；把字号加大到 15 又能让桌面端
变成 20px。DOM 实现的字号跟着断点走，两端都正常。只有折线图和散点图保留 SVG。

几条图表规则：

- 峰值染强调色，其余用纸灰。全染红等于没强调。
- 竖柱图的结构是 `列 > [数值][条容器 .bw][标签]`，`.bw` 撑满剩余高度，
  这样 100% 的柱子不会把标签挤出边框，峰值数字也不会顶到上文。
- 散点图必须有中位数参考线。长尾分布下点全挤在左下，没有参考线看着像渲染失败。
- 名字标签要避让：靠右的点改成右对齐往左放，纵向撞车就往下推 15px。
- 折线图首尾标签用 `text-anchor` start/end，否则第一个标签会被画布左边缘切掉一半。
- 图注写清口径，别写"如图所示"。

## 踩过的坑

1. `.sec-head` 用 flex 时说明文字会掉到编号右边变成第二列，要包一层 `.tt` 让它跟标题同列。
2. KPI 四栏直接 `repeat(4,1fr)` 会因为数字宽度不同显得间距不均，加 `border-left` 发丝线
   分隔，视觉上立刻变成有意为之的报头。
3. `text-wrap:balance` 对中文照样会断在词中间（「回／避型」），长标题要手动 `<br>`，
   不能只靠 balance。
4. 移动端截图验收要同时看 393×852（dsf=2, is_mobile）和 1440×1000 两个视口，
   并断言没有元素 `getBoundingClientRect().right > innerWidth`，否则会有横向溢出没发现。

## 验收

```bash
python -m wxchat_analysis html --data out/report_data.json --prose 正文.md -o 报告.html
```

- 0 JS 报错、0 横向溢出；
- 单文件、离线可打开，不引外部字体和脚本；
- 正文过 `python skills/human-writing/scripts/check_prose.py 正文.md`（硬禁令清零）。
